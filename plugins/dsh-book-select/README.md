# dsh-book-select

图书馆中文图书采购的选书工作台：先把 `doc/` 里 n8n 工作流的两阶段筛选搬成插件——**阶段一**用确定性硬规则预过滤（不花模型调用），**阶段二**把剩下的书分批交给大模型，按分类号规则与内容排除规则判定「通过 / 排除 / 待复审」，结果可人工改判、可导出 CSV，并能就规则本身与实现设计提问。

## 安装

前置条件：Node.js ≥ 20，DeepSeek Harness（DSH）≥ 0.2.0（`package.json` 的 `engines.dsh` 已声明；版本不匹配时 DSH 会拒绝安装，可用 `dsh plugin --profile <profile> allow-version dsh-book-select@0.1.7 --dsh-version <你的版本> --accept-risk` 放行）。插件本体零第三方运行时依赖，只需把本包装进你的 DSH profile。

**方式一：安装 tarball（推荐给别人）**

下载 `dsh-book-select-0.1.7.tgz` 后：

```bash
dsh plugin --profile <你的 profile> add <绝对路径>/dsh-book-select-0.1.7.tgz
```

也可以在 GUI 的「插件」面板里，把 tarball 的**绝对路径**填进安装框。DSH 会把它按 `pnpm add file:...` 装进 profile，自动把本包追加进 `dsh.profile.bundles` 并加载它的 `cordis.patch.yml`——不需要手改 profile 的 patch 文件。装完重启 DSH，浏览器硬刷新（Ctrl+Shift+R）。

**方式二：安装解压后的目录**

解压源码 zip 得到 `dsh-book-select/` 目录后：

```bash
dsh plugin --profile <你的 profile> add <绝对路径>/dsh-book-select
```

目录方式装进去的是「链接」依赖，你改源码即时生效，适合自己二次开发；tarball 方式则是拷贝进去的独立副本，两者互不影响。

**方式三：从 Git 仓库安装**

```bash
dsh plugin --profile <你的 profile> add github:<你的账号>/<仓库>
```

**装好之后**：左侧边栏出现 **选书** 图标。判定环节要调用大模型，请先在 DSH 里配好模型并选定当前会话所用模型，否则「开始 AI 判定」会提示缺少模型。

## 装上之后在哪里

左侧边栏多一个 **选书** 图标（`sidebar.panellist` 槽位，order 20，与「插件」「计划任务」并列），点它就在主面板打开选书工作台（`main` 槽位的 `book-select` 键）。工作台是应用级的一个共享清单：左侧面板切过去再切回来、或换一个会话，看到的都是同一份书目；对话里让 agent 调 `book_select` 工具操作的也是这份清单。

## 用法

1. 点左侧边栏的「选书」图标。
2. 导入书目：点「选择文件」，选一个 Excel 征订明细（`.xlsx`，默认）即可，导入后立刻预过滤；`.csv` / `.tsv` / `.txt` / `.json` 同样支持。表头按别名识别（书名/题名、定价/价格、中图分类号/分类号、内容提要/内容简介、页数/页码…），没有表头时按 `序号、书名、价格、出版社、ISBN、责任者、出版年、分类号、内容简介、版次、页码` 的位置顺序解析。命中硬规则的书直接进「排除」并写明原因；敏感词命中不再直接排除，而是变成随书附带的「预筛提示」交给模型按内容判断。
3. 点「开始 AI 判定」。按批（默认 15 本，可调 5–40）调用当前会话选定的模型，进度条实时走。**同一阶段内默认并发 3 批同时判定**（可调 1–6，「并发」下拉就在「每批」旁边），总耗时因此约是串行的三分之一；两阶段之间仍串行——先跑完「待判定」，再跑「失败重试」。**只判「待判定」的书**：已经有结果的（通过/排除/待复审）不会被重新送给模型，所以中断后再点一次是从断点继续，不重复判定、不重复计费。某一批调用出错（超时、模型返回空、JSON 截断重试仍失败）时，这一批进**「失败」**桶并记下错误原文，不会当成「待复审」；后面的批次照常跑完。遇到 provider 限流时该批**自动退避重试同一批**（2/4/8 秒，优先用 provider 给的重试时间），不会直接算失败；连撞 3 次仍失败才进「失败」桶。等「待判定」全部清空后，主按钮会变成「重试失败书目」，再点一次就只重跑失败的那些；同一轮里刚失败的批不会立刻反复重试。判定途中点「取消」时，**在途的那几批保持「待判定」**，下次运行接着判，不会被算成失败。每完成一批，统计卡、进度与表格行都会自动刷新（页面约每秒轮询一次宿主状态，书超过 1000 本时行数据改为每 3 秒拉一次）；判定若是从 agent 工具发起的，页面也会在 3 秒内发现并同步。
4. 看结果：顶部一行统计（总数/通过/排除/待复审/待判定/失败）、一行工具条（状态筛选 + 搜索 + 导出）；书目表占满剩余高度，表头冻结、行内滚动，书名默认两行截断（点书名展开内容简介、ISBN、版次与预筛提示）；**判定依据 / 改判内容是完整显示的**，长文本自动换行、保留原有断行，不再两行截断。每行的下拉框可人工改判（`source` 变成“人工”，统计同步）。表格**分页显示**（默认每页 50 条，可选 20/50/100/200）：底部有「首页 / 上一页 / 页码 / 下一页 / 末页」与每页条数选择，当前页高亮；切换筛选、搜索或导入新清单会自动回到第 1 页。导出始终包含全部匹配记录，不受分页影响。
5. **批注**：表格最后一列是「批注」，写你自己的判断（这本的作者对路、可以留着、封面要重做……）。点格子直接输入，失焦或 Ctrl+Enter 保存；批注**不影响判定结果**，只跟着这本书走——随清单存进历史存档，导出时作为最后一列带出去，搜索框也能搜到批注内容。
6. 「导出 CSV」按**当前视图**导出——顶部状态标签选哪个就导出哪一批（选「全部」导出全部，选「通过」导出通过的，选「失败」导出失败的），搜索框里有关键词时也只导出命中的那些；按钮旁会写明这次导出的是什么，例如「导出 通过 5 本（搜索「教材」命中）」。文件带 BOM，Excel 直接打开不乱码；文件名带 `-all-` / `-passed-` / `-failed-` 等当前标签名便于区分。导出保留导入时的**全部原始列**（列名、列序、单元格原值都不动，例如 `重复`/`载体`/`预订套数`/`读者对象`/`主题`/`订购号` 这些规则用不到的列也在），只在末尾追加五列：`状态`、`判定依据 / 改判`、`判定来源`（硬规则/大模型/人工）、`敏感词提示`、`批注`。
7. 「历史」按钮：每次导入会存一份清单，之后每判完一批都会就地更新同一份存档（含尚未判完的书），所以中途停掉也不会丢已经判出的结果。点「历史」列出全部存档（文件名、更新时间、总数与各状态的个数），点「载入」把那一份连同判定结果一起恢复到工作台，点「删除」从磁盘移除。最多保留 40 份，旧的自动清理。
8. 「规则说明」页列出全部硬规则（含本次命中数）、九类分类号规则、内容排除规则、I 类出版社白名单与敏感关键词，以及模型的输出契约。
9. 「设计问答」页可以问规则与实现的任何细节（为什么阈值是 500 元、批大小怎么选、再加一条规则要改哪里……）。回答只依据规则原文与本文档所述实现，规则没写到的地方会直说未覆盖。

## 批次监控

判定开始后，进度条旁边会出现「批次监控」按钮和一枚徽标（在跑时显示「N 批在跑」，跑完显示「已完成 N 批」）。点开（或每轮判定自动展开一次）可以看到：

- **在跑的批**：每批一行——批号、本数、书名、当前阶段（调用模型中 / 解析返回 / 限流退避 N 秒后重试 / 拆批重试 / 写回判定）和已耗时。耗时在本地每秒跳动，不必等下一次轮询。
- **已完成的批**：批号、本数、用时、三桶计数（通过/排除/待复审）与该批的 token 用量；默认只列最近 10 条，点「展开全部 N 批」看完整报告。
- **本轮汇总**：总耗时、平均每批耗时、最慢的一批，以及本轮 token 用量（输入 / 输出 / 合计 / 平均每本）。
- **token 条**里的「每批固定规则提示 ≈ N 输入」是这轮里各批输入 token 的最小值——规则提示词每批都要重发一遍，所以它能直观说明「批大小调大更省」。

跑完之后面板不会消失，它就是这一轮的**批次报告**：每个批次的记录都随存档一起落在 `$DSH_HOME/book-select/history/<id>.json` 的 `job.batchLog` 里，下次从「历史」载入那份清单时还能看到当时的批次报告。

token 数字来自模型调用返回的 usage 块（DSH 的 llm 流在 `finish` 之前会推一段 usage），只统计**插件自己发出的调用**，不换算金额（金额需要每模型单价表，容易过期反而误导）。

## 规则从哪来

`doc/图书馆图书采购筛选工作流-new.json` 是原 n8n 工作流，抽出的规则原文与脚本在 `doc/extracted/`。迁移时保持语义等价：

| 阶段 | 原工作流 | 本插件 |
| --- | --- | --- |
| 硬规则预过滤 | `预过滤.js`（页码→价格→影印→I 类白名单→关键词，else-if 首个命中） | `lib/rules.js` 的 `prefilterBook()`：页码、价格、影印、I 类白名单四条同序同判据；关键词改为 `keywordHintOf()` 生成「预筛提示」，不再直接排除 |
| AI 判定 | `Message a model` + `AIPROMPT_Message a model.md` | `lib/rules.js` 的 `AI_RULES` 原文作 system prompt，`lib/screening.js` 组装与解析 |
| 结果解析 | `解析AI结果1.js`（去换行 → `JSON.parse`） | `parseScreeningJson()`：去围栏、截取 `{}`、尾逗号与全角引号兜底 |
| 状态回写 | data table 的 `status/reason` 列 | 内存状态 + 状态机 `pending/passed/rejected/review/failed`，人工改判为最终口径 |
| 分批 | 50 本/批 | 5–40 本/批（默认 15），并发 1–6 批（默认 3）；单批调用失败进「失败」桶，待判定清空后再整批重试；限流时退避重试同一批 |
| 输出 | 三个 xlsx | 按筛选导出 CSV（浏览器侧生成，Host 无写盘权限） |

有意的差异：

- **敏感词只提示、不直接排除**：原工作流在“书名+内容简介”上做子串匹配，会把“综述里提到日本案例”“简介写拒绝心灵鸡汤”这类书误杀。这里仍计算命中词，但作为 `预筛提示` 字段随书交给模型，并在 `AI_RULES` 里明确要求“忽略关键词本身、按内容判断”。
- **不猜页码**：原脚本对“不以页结尾”的页码串一律放行，这里保持同样判定，只是把它记为“未提供页码”，不阻断；表格里显示「—」并有一行说明。
- **漏判必落桶**：模型没提到的书自动转「待复审」而不是丢弃，保证每本书都有归属。
- **失败与待复审分开**：原工作流把整批调用异常也写进同一个待复审桶，人分不清“模型说需要人看”和“模型根本没判”。现在前者仍是「待复审」，后者是「失败」并保留错误原文；重跑只重试失败的书，且排在待判定之后。
- **规则编号保留原样**（1–12、15–26，原工作流本身缺 13/14），这样历史数据里的“规则第X条”仍然对得上。
- **输出格式收紧了提示词**：要求只输出一个 JSON 对象、不要代码块围栏，并把“每本书必须且只能出现在一个数组里”写进 prompt。

## 扩展

- 阈值、白名单、关键词、九类分类号规则、内容排除规则、给模型的 system prompt，全在 `lib/rules.js` 顶部；`AI_RULES` 是判定口径的唯一来源。
- 新增一条内容排除规则：往 `CONTENT_RULES` 加 `{ n, text }`（`n` 用下一个未占用的编号），改完重启插件条目，然后在「规则说明」页确认它出现在列表里，再拿示例数据跑一次判定看是否命中。
- 表头别名、位置字段顺序在 `lib/parse.js` 的 `HEADER_ALIASES` / `POSITIONAL_FIELDS`。
- 批大小边界在 `index.js` 的 `BATCH_MIN/BATCH_MAX/BATCH_DEFAULT`；并发度边界在 `index.js` 的 `CONCURRENCY_MIN/CONCURRENCY_MAX/CONCURRENCY_DEFAULT`，批次池与冷却闸在 `lib/scheduler.js`。

## 实现结构

```
package.json        dsh.bundle.patch + dsh.client（web / immediately / inject）
cordis.patch.yml    插入 book-select 条目（带重复挂载保护）
index.js            Host 入口：/book-select/api/* 路由、内存状态、分批任务、批次报告（job.batchLog）、book_select 工具
client.js           浏览器入口：注册 sidebar.panellist 图标 + main 面板工作台组件（批次监控面板在这里）
lib/rules.js        规则常量 + 预过滤实现 + 给模型的 system prompt
lib/parse.js        xlsx / CSV / TSV / JSON 解析与字段归一化
lib/screening.js    模型调用（llm.stream 聚合成文本、接住 usage 块、阶段回调）、输出解析、设计问答
lib/scheduler.js    批次池（有界并发）、共享冷却闸（限流时让所有 worker 一起等）
locale/*.json       插件卡片标题与描述（中英）
```

- **宿主与浏览器怎么通信**：Host 半边在 `/book-select/api` 挂一个 prefix 路由，只接受 POST，先用 `connection.requestRejection` 做同源检查，再按路径尾段分派到 `operations` 表。UI 用同源 `fetch` 调同一张表，所以界面与工具的行为不会分叉。
- **模型调用**：走 `ctx.llm.stream()`，模型取 `agentDefaultModel.currentSelection()`（即当前会话选的模型），判定 `temperature: 0`、`maxTokens: 16000`（推理模型的思考也吃这份预算，太小会整批空返回，此时会按 `/没有返回任何文本|JSON/` 判定为可恢复错误并自动对半拆批重试，最多 3 层）；限流（失败码 `RATE_LIMIT`）不拆批，而是退避后重试同一批，最多 3 次；问答 `temperature: 0.2`、`maxTokens: 2600`，并限制默认 400 字以内以免被截断。`lib/screening.js` 还会把每次调用推来的 usage 块与当前阶段（调用/解析/退避/拆批）通过 `onUsage` / `onStage` 回调报给 Host，Host 据此写出批次报告。
- **给 Agent 的工具**：`book_select`，参数与 HTTP 接口一一对应（`action` 取 `status/import/sample/run/cancel/results/set_status/set_note/rules/history/load_history/delete_history/ask/reset`）。默认操作与侧边栏面板同一个清单（键 `workbench`），所以“帮我把这份书单筛一遍”这类话，Agent 直接调工具即可，界面上会看到同一份结果。
- **状态放哪**：当前工作清单在 Host 进程内存里，按清单键（UI 固定 `workbench`）存。存档另存为 JSON 文件：每份清单一个文件，放在 `$DSH_HOME/book-select/history/<id>.json`（默认 `C:\Users\<你>\.dsh\book-select\history`），导入时写一次、每批判定后再写一次、人工改判与批注也写，最多保留 40 份。插件重载会丢掉内存里的当前清单，但历史存档还在，点「历史」载入即可继续。

## 已知边界

- `.xls`（旧二进制格式）会明确拒绝并提示另存为 `.xlsx`。
- xlsx 里的日期单元格按序列号原样读出（书目数据基本不用日期列）。
- 单次导入上限 5000 条；表格按页渲染（默认每页 50 条，最多 200 条），筛选与导出不受分页限制。
- 并发度越高越容易撞 provider 限流；插件会自动退避重试同一批，但并发调到 6 路仍频繁失败时，把「并发」调回 1–2 就能退回串行行为（不改变判定口径）。
- 批次报告按批次粒度记录：拆批重试时同一行只显示最后一次上报的阶段；token 只统计插件自己发出的调用，不含 DSH 对话本身的开销，也不换算金额。
- 批注是纯文本、只属于这一本书，不参与任何规则判定；单元格默认两行高，拖右下角可以拉高写长一点。
- 判定质量取决于模型对分类号与内容简介的理解；信息不足的书应落在「待复审」而不是硬判——这也是规则里“宽进严出”的本意。
